# AXM Magic Box

## Informal name

**AXM Magic Box**

## Technical name

**AXM Node Cartridge**

## End goal

The Magic Box is the convenience form of AXM: a compact cartridge-like body that can carry a very large capability world as deterministic nodes, state, relationships, recipes, contracts, references, and dormant payloads while only realizing the subset needed for the current task.

It should feel to the user like a small box that can unfold into a much larger world when requested.

That feeling must come from real software structure, not hidden claims of impossible compression.

## Intended experience

A future user should be able to:

1. load one cartridge into a compatible host;
2. inspect what the cartridge contains and what is available;
3. request a capability or workflow;
4. let the host resolve the smallest required node set;
5. activate/materialize only those parts;
6. receive the result;
7. preserve any new state that should persist;
8. let inactive machinery return to dormancy.

The same cartridge may expose very different interfaces on different devices while preserving one underlying capability/state body.

## Why this exists

AXM can keep publishing capabilities, tools, research, and larger wired monoliths. The Magic Box asks a separate question:

> How much of that world can be represented as compact dormant capability potential instead of duplicated always-active software?

The goal is convenience, portability, low active footprint, and composition.

## Not the goal

The Magic Box is not intended to:

- own or gate ideas;
- hide capabilities that are otherwise available;
- make free AXM paths intentionally worse;
- claim infinite compression;
- pretend a node declaration is a working implementation;
- replace provenance with one opaque binary;
- require AI to function when deterministic/human operation is enough.

## Product boundary

If the research matures into a paid/support product, payment is for the work already done to make the cartridge compact, indexed, wired, tested, portable, maintained, and convenient.

Someone who does not buy it should still be free to use the available AXM material and do the assembly work themselves where those source licenses permit.

**Destination reachable for free; finished bridge may cost money.**

## Magic-box test

A future release deserves the name only if it can honestly answer:

- What capabilities are represented?
- Which are embedded versus referenced?
- Which are dormant versus active?
- What exact state is currently loaded?
- What did activation cost?
- What is executable on this host?
- What failed or remains unavailable?
- Can the cartridge be inspected, exported, and resumed without hidden chat memory?

If those answers are unavailable, the box is not mature yet.
